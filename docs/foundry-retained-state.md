# Disposable runtime, retained state, and lifecycle evidence

This contract applies to future Foundry-managed Apps, system containers and VMs. The runtime (SYSTEM/image/root filesystem) is reproducibly replaceable; scratch is disposable; retained user files, user configuration, application state and service identity have separate ownership and retention. Secrets are resolved from protected external references, not embedded in the artifact. A fully stateless workload may explicitly declare zero retained slots; the configuration recipe is still pinned. A workload may not hide durable state in the writable runtime. A physical binding must be independently verified, not inferred from a logical slot or digest. App/VM ownership does not imply ownership of datasets, volumes or disks.

Each lifecycle operation, including create, start, stop, replacement/update, backup/restore, rollback and retirement, follows observe/discover -> plan -> apply -> verify. Read-only planning uses exact desired artifact and observed target profile, identity and state, resource ownership, persistent bindings, previous artifact and recovery compatibility. Apply is separately admitted, bounded, single-writer and tied to the reviewed plan; ambiguous results require fresh observation before another action. Verify independently checks actual postconditions and retained state, then re-plan must converge to NOOP. No forced or destructive shortcut. Event-like operations retain the existing durable token semantics. Retirement retains user data unless separately authorized under a distinct storage operation.

Reproducibility = pinned build/configuration/dependency inputs and independent materialization evidence; repeatability = repeat the lifecycle on clean fixtures; idempotence = deterministic re-plan/no-op and no duplicate mutation on replay; reversibility = prior compatible artifact, protected backup, tested restore and a reviewed rollback operation, with schema migrations independently qualified. These are distinct claims. Hash syntax does not authenticate evidence. A rollback cannot recover newly written user data by simply reverting a runtime snapshot; quiesce/backup and schema compatibility are required. State schema changes, cross-target migration, and irreversible changes remain distinct held worksets.

The source-only guard binds a logical retained-state contract digest to the existing artifact envelope and compares supplied before/after references to reject missing slots, aliasing, changed controlled sentinels and unbound recovery references. The result never establishes physical separation, real restore, live ownership or apply permission. Synthetic sentinels are for controlled tests, not a requirement that all production files never change. Same-target/same-layout replacement only; no native calls, no second planner, no source of site ownership. Existing App v2 planner and native adapter admission remain unchanged.

Qualification: F0 exact source/profile; F1 immutable runtime + independent state bindings and reproducible build; F2 independent create/readback; F3 replace runtime, rebind preserved data/config, stop/start/update and recover; F4 repeat/no-op, ambiguous response and replay tests; F5 retained-state retirement/recreate and verified rollback/restore with controlled marker checks. Require negative fixtures for foreign or aliased state, missing binding, incompatible schema, failed replacement/restore and stale observations. Preserve existing stage meanings and exact-target evidence; do not inherit results between kinds.
