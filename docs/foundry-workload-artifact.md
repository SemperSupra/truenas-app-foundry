# Typed workload artifact envelope (source candidate)

Existing App v2 lifecycle and immutable deployment-artifact validation are unchanged. This first source-only seam adds a common, closed identity envelope for Apps, system containers and VMs. It wraps identities, not native payloads. Adapter labels and format pairs are candidate vocabulary, not proof of installed API methods or compatible imports. The native VM and system-container adapters remain unimplemented here. Hyper-V and TrueNAS VM variants can share a product build/data-contract identity and independently hashed platform artifact identities. A format label does not establish bootability or conversion correctness.

The envelope requires exact product build, target profile, platform, version, artifact and retained-data contract digests. It has no paths, network attachment, secrets, arbitrary commands, live ownership state or execution authority. It returns IDENTITY_ONLY; runtime qualification, ownership and apply remain false. App operations still require the existing v2 planner and exact App artifact validation. Future native adapters consume the existing compute materializer and must independently prove native state/payload contracts. The same build identity is not a live instance identity, disk compatibility or migration guarantee. Never authorize DATA deletion through workload ownership. All fixtures are fictional.
