# Shared model and generative asset bindings

Consumer qualification supplement to the existing [Foundry lifecycle contract](../../../docs/foundry-lifecycle.md) and [Model Artifact Foundry hydration contract](https://github.com/SemperSupra/model-artifact-foundry/blob/6bc5750dcd947cbbf8b3a11e80afbabd81c19ed6/docs/contracts/hydration.md). This is not another catalog, model manager, download service, inference scheduler or site deployment authority.

## Authority and storage

- MAF owns upstream identity, exact representation (OCI or gated/local content-manifest), acquisition provenance, verified file hashes and general compatibility evidence. The consumer owns selection of an exact approved representation and product/load qualification. Do not infer compatibility from extension or model name.
- Hydrate once into independently owned durable verified storage. Project per-consumer read-only views with stable logical filenames, derived from the selected manifest. Never mount the entire cache, staging, private model collection or raw credential area into every app. Use separate access-controlled views. Bind exact selected identities to the immutable runtime and job plan; retain old views for active jobs and rollback. Prefer real read-only mount enforcement rather than permissions alone. No in-place edits, runtime auto-install, or global GC based on app deletion.
- The logical model, base architecture, adapter target layers, precision/quantization, complete component set (including tokenizer/config/encoder/VAE dependencies), file format, runtime loader/version, license and tested compatibility govern reuse. A converted representation gets its own identity and derivation link. Deduplicate identical verified bytes, not similar names. Cross-architecture adapter conversion is not assumed possible.
- Keep runtime extensions/custom nodes, executable filters and model Python code as reviewed, pinned runtime/dependency artifacts. Plain model configuration, manifests, tokenizer files, LUTs, masks, reference media, workflows and prompts are data; share only according to compatibility, ownership and access. User-editable originals stay outside immutable model artifacts. Separate per-app mutable metadata, databases, cache, workflow execution state, credentials and output staging; publish accepted outputs to the user library by a verified promotion/export operation. Do not allow multiple independent writers to a SQLite database or undocumented app state directory.
- Runtime model loading and GPU/RAM residency are separate from disk sharing. Prefer one inference service/backend for clients that speak its qualified API; independent runtimes can consume the same disk bytes but may load duplicate weights into accelerator memory. Device/resource admission and scheduling belong to the existing inference/operation authority, not this file.

For generic speech, vision, music and LLM servers, share only identical supported representations. CTranslate2, GGUF, MLX, ONNX, PyTorch safetensors and Diffusers layouts are not equivalent representations; different versions or converted bundles need separate selections and compatibility evidence. A shared repository or cache does not imply a common process or accelerator memory. Use a local-only gated acquisition record where redistribution is not licensed; no model downloads, licensed content, personal files or private bindings are needed for this public probe.

## Lifecycle gate

Observe/discover consumer paths, capabilities, exact app and artifact identities, license, immutable verified cache, ownership, storage/disk budget, active jobs and required component graph. Plan selected representation IDs/hashes, per-consumer view and generated config, independent mutable state, required loader tests, snapshot/rollback and cleanup. Apply only authorized verified hydration, view publication, registration or backend binding; keep existing view for active leases and NOOP on identical observed state. Verify actual application inventory and exact bytes, then actual load and task-specific inference in a separately admitted test; test no overwrite/delete/cross-worker state bleed and replacement retaining user data. Unknown path/format/compatibility fails closed. Never label enumeration as model-load or product fitness.

## First executable evidence increment

The existing ComfyUI CPU job runs `lifecycle/qualify_comfyui_shared_assets.py` after the same-image replacement experiment. Two actual isolated instances read one uniquely owned read-only fixture volume; explicit extra-model-paths files map non-default categories to that shared volume. Each instance has its own user/input/output volumes. It verifies model enumeration via /models/{category}, exact equal SHA-256s of tiny synthetic safetensors, rejected writes, independent HTTP settings and NOOP identity. These are intentionally not real model weights and are not loaded. This does not yet qualify Swarm remote, Invoke in-place registration, ACE-Step startup, MAF hydration, GPU or inference. Only public disposable CI fixture resources are created/deleted.
